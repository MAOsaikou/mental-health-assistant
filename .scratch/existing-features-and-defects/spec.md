Status: ready-for-agent

# 现有功能与已知缺陷

## Problem Statement

维护者和后续 agent 接手「小光心理助手」时，没有一份以用户视角写成的基线：系统现在能做什么、角色怎么分、哪些行为是有意设计、哪些是已经暴露的缺陷。结果是改功能时容易把独立落地页当成主产品、把规则引擎情绪分析当成模型诊断、或在修缺陷时顺手发明不存在的能力（咨询师角色、找回密码等）。

需要一份规格，把**当前已上线的主产品行为**和**已知缺陷**钉死，作为后续修缺陷、补测试、加功能的对照，而不是一份新功能设计。

## Solution

以普通用户和管理员在主产品（Vue 前台 + Spring Boot 后端）上能完成的事为范围，整理一份「现有功能与已知缺陷」规格。行为以 `/api` HTTP 表面为准；管理端列表错标等视图层问题在规格中登记，不另开接缝。独立静态落地页不纳入主产品。后续工作对照本规格：已列出的能力要保持；已登记的缺陷可修；未列出的能力默认不存在。

## User Stories

1. As a 访客, I want 打开首页看到小光心理助手的介绍和入口, so that 我知道这是什么产品、可以从哪里开始。
2. As a 访客, I want 不登录也能浏览已发布的知识文章列表, so that 我先了解内容再决定是否注册。
3. As a 访客, I want 不登录也能打开一篇已发布知识文章并阅读正文, so that 我能直接获取心理科普信息。
4. As a 访客, I want 阅读文章时系统增加该文阅读量, so that 热门内容能反映真实阅读情况。
5. As a 访客, I want 通过用户名、邮箱和密码注册为普通用户, so that 我能使用咨询和情绪日记。
6. As a 访客, I want 注册时若用户名或邮箱已被占用则得到明确失败, so that 我知道该换一个账号。
7. As a 访客, I want 用用户名或邮箱加密码登录, so that 我能进入自己的账号。
8. As a 访客, I want 登录失败时看不到「账号是否存在」一类的精确提示泄露, so that 外人不能靠试错枚举账号。
9. As a 刚登录的普通用户, I want 被带到前台而不是管理后台, so that 我使用的是给用户的界面。
10. As a 刚登录的管理员, I want 被强制带到数据分析页, so that 我不会误入前台用户流程。
11. As a 普通用户, I want 即使用户猜到后台地址也无法进入 `/back`, so that 运营功能只对管理员开放。
12. As a 管理员, I want 访问前台路由时被送回后台, so that 两种角色的界面互不混用。
13. As a 未登录访客, I want 打开咨询、情绪日记或个人中心时被送到登录页, so that 私密功能不会在未认证时使用。
14. As a 已登录用户, I want 访问令牌过期后能靠刷新令牌静默续期, so that 短时间离开不必重新登录。
15. As a 已登录用户, I want 主动退出后访问令牌和刷新会话都失效, so that 同一浏览器里别人不能接着用我的登录态。
16. As a 被禁用的用户, I want 即持有旧令牌也无法通过身份校验, so that 停用账号立即生效。
17. As a 普通用户, I want 在首页看到近 7 天心情趋势, so that 我能一眼看到最近情绪变化。
18. As a 普通用户, I want 从首页进入聊聊、情绪日记或知识文章, so that 三条主路径都找得到。
19. As a 普通用户, I want 新建一次咨询会话并开始跟小光说话, so that 我有一个独立的聊天线程。
20. As a 普通用户, I want 小光以流式方式回复, so that 我不用等整段生成完才能开始读。
21. As a 普通用户, I want 小光保持陪伴、倾听、非诊断的人设, so that 对话不像诊疗结论。
22. As a 普通用户, I want 在对话中表达自伤或自杀相关危机时立刻收到固定的安全引导（含求助热线方向）, so that 这类内容不交给模型自由发挥。
23. As a 普通用户, I want 侧边栏看到基于当前会话的情绪分析摘要, so that 我能看到系统对这次对话的规则解读。
24. As a 普通用户, I want 查看自己的历史咨询会话列表, so that 我能回到以前的聊天。
25. As a 普通用户, I want 打开某次自己的会话并看到历史消息, so that 上下文可以接着聊。
26. As a 普通用户, I want 删除自己的咨询会话, so that 我不想保留的对话可以去掉。
27. As a 普通用户, I want 不能打开或删除别人的咨询会话, so that 聊天内容只属于会话主人。
28. As a 普通用户, I want 在未配置自有模型密钥时使用平台额度与小光对话, so that 我可以先试用。
29. As a 普通用户, I want 平台免费额度用尽时被明确告知需要自备密钥, so that 我知道为什么聊不下去。
30. As a 已配置自有密钥的普通用户, I want 对话不再受平台免费次数限制, so that 我能继续使用咨询。
31. As a 管理员, I want 使用咨询时不受平台免费额度限制, so that 运营自测不必先填密钥。
32. As a 普通用户, I want 在个人中心配置、更新或清除自有 API Key、接口地址和模型名, so that 我能改用自己的模型服务。
33. As a 普通用户, I want 个人中心能看到自己还剩多少平台免费次数, so that 我能决定要不要配置密钥。
34. As a 普通用户, I want 自有密钥在服务端加密存放且个人资料接口不回传明文, so that 密钥不会出现在普通资料响应里。
35. As a 普通用户, I want 当天写一条情绪日记（心情分、主导情绪、触发因素、正文、睡眠、压力）, so that 我能留下当天的情绪记录。
36. As a 普通用户, I want 同一天不能再提交第二条情绪日记, so that 「每日一条」被守住。
37. As a 普通用户, I want 提交日记后立刻看到一份分析说明, so that 我知道系统如何解读这条记录。
38. As a 普通用户, I want 看到的「分析」实际是规则引擎结果而不是模型诊断, so that 我不会把它当成医学结论。
39. As a 普通用户, I want 查看自己最近的情绪日记历史, so that 我能回顾过去的记录。
40. As a 普通用户, I want 打开某条自己的日记详情, so that 我能重读当天写了什么。
41. As a 普通用户, I want 不能读取别人的情绪日记, so that 私密记录不被其他用户看到。
42. As a 普通用户, I want 在个人中心修改昵称、邮箱、手机、性别、生日, so that 资料保持正确。
43. As a 普通用户, I want 上传头像并在界面上看到新头像, so that 账号有可识别的形象。
44. As a 普通用户, I want 用旧密码改成新密码, so that 我能轮换口令。
45. As a 普通用户, I want 改密时旧密码错误会被拒绝, so that 别人不能在已登录设备上随便改我的密码。
46. As a 管理员, I want 打开数据分析页看到用户量、日记量、会话量和平均情绪分等总览, so that 我能判断平台使用情况。
47. As a 管理员, I want 看到情绪趋势、咨询统计、用户活跃一类图表数据, so that 运营有时间维度的观察。
48. As a 管理员, I want 分页管理知识文章（含草稿、已发布、已下线）, so that 我能维护科普内容生命周期。
49. As a 管理员, I want 新建、编辑、改状态、删除知识文章并上传封面, so that 内容可以完整运营。
50. As a 管理员, I want 前台游客只能看到已发布文章, so that 草稿和下线内容不会公开。
51. As a 管理员, I want 分页查看全站咨询会话列表, so that 我能处理运营或安全抽查。
52. As a 管理员, I want 默认看到脱敏后的咨询内容, so that 日常浏览不暴露完整私密对话。
53. As a 管理员, I want 在明确选择「查看完整对话」后才看到原文, so that 完整内容是有意揭开的。
54. As a 管理员, I want 分页查看全站情绪日记, so that 我能抽查或处理风险记录。

56. As a 管理员, I want 删除某条情绪日记, so that 违规或需清理的记录可以去掉。

## Implementation Decisions

- 主产品是一套前台 + 一套后台，共用同一后端 HTTP 表面；角色只有普通用户与管理员，不存在咨询师。
- 身份：访问令牌为短时 JWT，刷新令牌为 HttpOnly Cookie 会话；禁用账号会使令牌校验失败；登录后按角色把用户关进前台或后台。
- 公开可读：登录、注册、刷新令牌；已发布知识文章的列表与详情；知识分类树；已上传的静态文件。咨询、情绪日记、个人资料、全部管理端能力需要登录，且管理端还需管理员角色。
- 咨询是与小光的流式对话：先建咨询会话，再对同一会话发用户消息并以事件流回收回复；会话与消息落库；仅会话主人可发消息和删除；管理员可读全站会话。
- 小光人设是陪伴与倾听、不做诊断；危机关键词命中时走固定安全回复，不调用模型。
- 平台密钥下普通用户有固定免费发言次数（当前为 20）；管理员或已配置自有密钥的用户不受该次数限制。自有密钥、接口地址、模型名由用户在个人中心维护，服务端加密存储，资料接口不回说明文。
- 对话记忆窗口有上限（约最近 30 条消息）。更早内容可能不在模型上下文中，但历史消息仍可从存储中给用户查看。
- 情绪日记每用户每天至多一条。提交后由规则引擎生成分析并写入分析字段；该结果不是大模型诊断。管理端查看日记和咨询正文时默认脱敏，需显式揭开才返回完整内容。
- 知识文章有草稿 / 已发布 / 已下线；前台列表与详情只暴露已发布。管理员可增删改并切换状态、上传封面。
- 数据分析总览仅管理员可调。当前「活跃用户」按用户资料更新时间是否落在当天计算，不是按咨询或日记行为。
- 咨询相关写操作有按用户的速率限制。
- 文件上传后以相对路径提供访问；历史路径中的业务目录拼写（`bussiness`）已对外，纠正拼写会破坏已有 URL，属兼容性决策而非笔误可随手改掉。
- 管理端若干列表的列标题与单元格内容错位、风险等级用数字展示、状态筛选占位符文案错误、规则分析结果在界面上写成「AI 情绪分析」：这些是已确认的视图层缺陷，HTTP 契约本身不依赖这些标题。
- 查询对象上心情分范围字段名少了一个字母（与前后端一致）。功能可用，但作为已知命名缺陷保留，修复时必须前后端一起改，避免只改一侧。
- 独立静态落地页是另一套展示，不调用主产品 `/api`，无账号、无数据库业务表。心情选择只在浏览器本地给出反馈。本规格不把它并进主产品实现。
- 不提供找回密码、邮箱验证、咨询师工作台、把落地页登录接到主用户表。

## Testing Decisions

- 好的测试只描述 `/api` 上的外部行为：状态码与业务结果、角色能否访问、脱敏是否默认开启、每日一条是否拒绝第二条、额度用尽是否拒绝平台密钥对话、危机输入是否返回固定安全回复而不是模型输出。不测 Vue 组件内部状态、不测规则引擎的私有计分公式、不测 SQL 或文件路径拼写。
- 被测模块就是 HTTP 表面背后的主产品能力：用户认证与资料、咨询会话与流式对话（含危机与额度）、情绪日记、知识文章、数据分析、文件上传。对需要模型的咨询流式路径，测试应注入可替换的模型适配器（或固定桩），而不是打到真实外网模型。
- 仓库里已有较低层先例：注册校验、咨询会话访问控制、危机关键词、隐私脱敏、JWT、限流、全局错误处理。本规格要求把「现有功能」的核验抬到 HTTP；已有单测可继续作为内部回归，但不作为本规格的主接缝。
- 管理端列标题、风险等级文案、筛选 placeholder 属于视图层已知缺陷：本规格登记它们，不为它们新增测试接缝。修复后用人眼看列表即可，不必为改几个 label 去搭前端测试框架（前端目前也没有测试脚本）。
- 数据分析「活跃用户」的定义以当前实现为准来做表征测试（按资料更新时间）；若以后改为真实活跃，应先改本规格再改行为。

## Out of Scope

- 独立静态落地页的改版、账号打通、把心情温度计写入情绪日记。
- 新角色（咨询师）、三方问诊、人工排班。
- 找回密码、邮箱验证、第三方登录。
- 把规则引擎升级为真正的模型情绪诊断或医疗级评估。
- 把访问令牌移出本地存储、生产级密钥托管、改默认数据库口令等运维加固（可另开规格；此处只记录风险）。
- 为修列标题而引入新的前端测试栈。
- 撰写领域术语表或架构决策记录（本规格不创建它们）。
- 扩展免费额度数值、更换平台模型供应商、加长对话记忆窗口——这些是产品变更，不是「现有功能」基线。

## Further Notes

- 产品名是「小光心理助手」，陪伴角色名是「小光」。用户口中的「聊聊」对应咨询；「读一读」对应知识文章；「我的」对应个人中心。
- 情绪分析、咨询侧栏摘要、日记提交后的说明，全部来自同一类规则判断，不是诊疗。文案若继续写「AI」，是缺陷而不是能力。
- `site/` 与主产品可以长期并存，但后续 agent 默认只改主产品，除非用户明确点名落地页。
- 本规格的 `Status` 为 `ready-for-agent`：可直接据此拆修缺陷工单或补 HTTP 表征测试，不必再分诊。拆票时每张工单一个文件，不要把缺陷清单重新糊成一份 tickets 合集。
